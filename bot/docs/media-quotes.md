# Медиа-цитаты и цепочки

## Использование

- `!цитата` ответом на сообщение сохраняет текст, фото, видео, GIF или кружок.
  Кружок отправляется квадратным видео со звуком. Подпись медиа сохраняется
  отдельной текстовой карточкой. Для альбома эта команда сохраняет выбранное
  сообщение; весь альбом можно переслать в ручную сборку.
- `/цитата` (также `/quote`) ответом на последнее сообщение собирает ветку
  ответов до корневого. Автор — автор корня; тексты объединяются пробелами,
  исходные слова и пунктуация не переписываются. Соседние ветки не добавляются.
- В личке `/цитата` без ответа запускает ручную сборку. Переслать сообщения
  по порядку, затем нажать «Собрать цитату». «Отмена» удаляет только черновик.
  Ручная сборка не запускается во время заполнения регистрационной анкеты.
  Telegram может скрыть id автора пересылки: тогда используется переданное
  им имя без попытки угадать аккаунт. Черновик действует сутки.
- Если начало цепочки неизвестно, бот предлагает явно подтвердить сохранение
  доступного фрагмента. Усечённый вложенный reply не считается корнем.
- Одна составная цитата имеет один номер и общий набор голосов. `!мудрость`
  показывает её полностью, топ/батл — превью и кнопки просмотра.

Текст длинной цепочки разбивается на карточки. Медиа остаются самостоятельными
частями в исходном порядке. Все части подписываются корневым автором; реальные
авторы каждой части также остаются в базе. Новые медиа-цитаты используют общий
поиск ФИО и исторических аватарок. Готовый результат переиспользуется по `file_id`;
при изменении подписи/исторического фото оформление будет собрано заново.

## Хранение и ограничения

В группах middleware сохраняет новые сообщения и их правки: текст, автора,
связь с родителем и Telegram `file_id`. Бот должен получать обычные сообщения
(администратор группы либо отключённый privacy mode). Старая история через
Bot API не загружается. Групповой журнал хранится 90 дней. Новые текстовые и
медиа-сообщения в личке также сохраняются для цепочек, но только на сутки.
Ответы во время заполнения регистрационной/другой FSM-формы не записываются.

`quote_messages` — журнал; `quote_contents` — снимок частей сохранённой цитаты
и `file_id` готовых материалов; `quote_jobs` — очередь; `quote_drafts` и
`quote_pending` — черновики и подтверждения. Существующие таблицы цитат/голосов
не меняются. Дополнительные таблицы создаются автоматически через `create_all`.
Удаление старого журнала не удаляет сохранённые цитаты.

До 100 исходных сообщений, 32 000 символов; файл до 20 МиБ, ролик/GIF до
60 секунд, видео не больше 4K по числу пикселей. До двух активных заданий
на пользователя и 20 на весь бот. Один worker, ffmpeg с двумя потоками
кодирования; отдельный Redis не нужен. Скачанные файлы временные и удаляются
после обработки. Исходные/готовые медиа постоянно на диске не копятся.

После перезапуска worker продолжает очередь и пропускает уже сохранённые
отправленные части. При аварии строго между отправкой в Telegram и записью
его ответа возможен повтор последней части: гарантировать exactly-once Bot API
не позволяет. Ошибочные/неготовые задания исключены из мудростей и новых батлов.
Данные, пришедшие во время короткого перезапуска, больше не сбрасываются через
`drop_pending_updates=True`.

## Обновление боевого flood

Коммиты `7030d78` (антивалыны/фото анкеты) и `405e814` (Диана/исторические фото)
уже предшествуют этой реализации. Достаточно обновить ветку `main` целиком.
Пуш в репозиторий сам по себе обновляет только трекер; бот `/root/flood`
нужно пересобрать отдельно. GitHub Secrets и токены копировать не нужно.

На сервере перейти в существующий checkout **ik-trecker-system** (путь может
отличаться от `/root/ik-trecker-system`):

```sh
cd /root/ik-trecker-system
git pull --ff-only origin main
export IK_TRACKER_BOT_SOURCE="$PWD/bot"
```

Перед первым обновлением сделать согласованную резервную копию базы работающего
бота (копия создаётся в прежнем примонтированном `database/`, с уникальным именем):

```sh
docker compose -f /root/flood/docker-compose.yml exec -T bot python -c 'import sqlite3,datetime; stamp=datetime.datetime.now().strftime("%Y%m%d_%H%M%S_%f"); source=sqlite3.connect("file:database/bot.db?mode=ro",uri=True); target=sqlite3.connect("database/bot.db.bak_before_media_"+stamp); source.backup(target); target.close(); source.close()'
```

Проверить конфигурацию без печати `.env`, затем обновить **тот же** сервис бота:

```sh
docker compose -f /root/flood/docker-compose.yml -f "$IK_TRACKER_BOT_SOURCE/deploy-from-tracker.yml" config --quiet
docker compose -f /root/flood/docker-compose.yml -f "$IK_TRACKER_BOT_SOURCE/deploy-from-tracker.yml" up -d --build bot
docker compose -f /root/flood/docker-compose.yml logs --tail=50 bot
```

Первый compose-файл оставляет прежние `.env`, проект `flood` и том базы.
Дополнительный файл меняет только источник сборки/имя образа. Код берётся
из `bot/` этого репозитория. Второй polling с тем же токеном не запускать.
Для следующих обновлений повторять `git pull` и ту же команду с двумя файлами.

## Проверка и откат

Проверить фото, видео со звуком, GIF, кружок; затем создать новую цепочку
ответов из нескольких сообщений и вызвать `/цитата` на последнем. Для старых
сообщений проверить подтверждение неполной цепочки и ручную сборку в личке.
Отдельно проверить `!мудрость`, `!топ цитат`, `!батл`, `!антивалыны` и старую
цитату Дианы. Новые команды доступны после пересборки именно бота.

Точка до реализации: **405e814**. Если потребуется откат, отменить только
коммит реализации через `git revert <коммит-реализации>` (сохранив историю),
отправить в оба remote и повторить сборку бота. Если после реализации были
другие изменения, сначала проверить совместимость отката. Дополнительные
таблицы/новые цитаты не удалять; рабочую базу из старого бэкапа поверх новых
сообщений не восстанавливать. Исправления Дианы и антивалын сохранятся.

Локальные проверки:

```sh
PYTHONPATH=bot python -m unittest discover -s bot/tests -v
```

Нужны зависимости бота, ffmpeg/ffprobe. Тесты используют временные SQLite,
синтетические фото/видео со звуком, не обращаются к Telegram и production-базе.
